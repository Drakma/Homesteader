feat(Assets): split HUD into toolbox parts - vitals, time-and-date, resources, speed, slots

The HUD is now a *toolbox* of standalone components rather
than a single assembled HUD. Each piece is its own UXML file
so it can be loaded independently in any scene context:

  Resources/HUDTree/Vitals.uxml       - 4 vital rows (W/S/T/H)
                                       with horizontal bar fills.
                                       Bound names: VitalWellnessFill,
                                       VitalWellnessPct, etc.
  Resources/HUDTree/TimeAndDate.uxml  - Season + Day + Clock,
                                       centered. Bound names:
                                       SeasonLabel, DayLabel, ClockLabel.
  Resources/HUDTree/ResourcesBar.uxml - 4 resource rows
                                       (water/electricity/bandwidth/fuel).
                                       Bound names: ResourceWaterLabel, etc.
  Resources/HUDTree/SpeedControls.uxml - 5 chip buttons (II, 1X,
                                       3X, 5X, 9X) under the time row.
  Resources/HUDTree/ToolbarSlots.uxml  - 10 free-floating bordered
                                       slots. NO container background.
                                       Bound names: ToolbarSlot0..9,
                                       ToolSlotLabel0..9.

Matching paired USS files give each piece its own styling.

In Resources/HUDTree/HudUI.uxml the combined SampleScene HUD
keeps the live layout: vitals on left, time+date+speeds centered,
resources on right, toolbar slots free-floating at the bottom.
The held-asset panel is REMOVED.

HudBindings.cs:
  - Resolves the by-name elements via Q() for each piece.
  - Vital bar fills have their `style.width` set per frame as
    a StyleLength(Length(barPercent, LengthUnit.Percent)).
  - Toolbar selected slot class toggled each frame using
    HudState.SelectedSlot.
  - Speed chip clicked events route to TimeSystem.SetSpeed.
