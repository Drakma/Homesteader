# Homesteader - Grid & Ground Texture Standards

This document is the single source of truth for world-grid scale and ground
texture/mesh resolution. Anything that places buildings, generates ground
tiles, or authors new ground textures **must** follow these numbers so tiles
line up seamlessly and texture crispness stays consistent across the game.

---

## 1. The Grid

| Property | Value | Source of truth |
| :-- | :-- | :-- |
| **1 grid cell** | `1m x 1m` | Design spec |
| **1 grid cell in Unity units** | `1 x 1` | `GameRules.Planting.GridSizeM = 1f` (`Assets/Scripts/Growth/GameRules.cs`) |
| **Unity unit scale** | `1 unit = 1 meter` | Engine default |

Unity 6's default world scale is 1 unit = 1 meter. Since
`GridSizeM = 1.0f`, one grid cell is exactly 1m on a side. All
building placement, snapping (`PlantingValidator.SnapToGrid` /
`PlantingValidator.GridSizeM`), and ground tiling must treat
**1 Unity unit as the atomic grid unit**.

The grid is accessed in C# via:
- `PlantingValidator.GridSizeM` — the cell size in meters (default `1f`).
- `PlantingValidator.SnapToGrid(Vector3 p)` — snaps a world point to the centre of its grid cell.
- `GameRules.Planting.GridSizeM` — the underlying data field, overridable by a `gamerules.json` mod (`grid_size_m` key).

## 2. Ground Mesh Tiles

Ground tiles are modular 3D meshes generated by
[`tools/generate_ground_meshes.py`](file:///c:/Users/casey/Desktop/Homesteader/tools/generate_ground_meshes.py)
and exported to both:

- `assets/ground/models/`
- `Homesteader/Assets/Homesteader/Assets/Ground/Meshes/`

| Property | Value |
| :-- | :-- |
| **Footprint** | `1m x 1m` (exactly 1 grid cell) |
| **Slab height** | `20cm`, with a `2cm` inset bevel on the underside for seamless edge tiling |
| **Origin** | Centered at local `(0,0,0)`, top surface at `Y=0` |
| **UV mapping** | Full `0.0 - 1.0` across the top face per tile (1 texture repeat = 1 grid cell) |

A ground mesh tile is **always exactly one grid cell**. Never author a ground
tile mesh at 2x2 or other multi-cell footprints — it will desync from the
building-placement grid and break snapping/highlighting.

Specialized variants (`SM_Tile_Farmland_Furrows`, `SM_Tile_Road_Asphalt`,
`SM_Tile_WoodPlanks`) still occupy the same 1x1m footprint; only their
surface geometry (furrows, road crown, plank subdivision) varies internally.

Freestanding clutter meshes (`SM_Clutter_TallGrass`, `SM_Clutter_Pebbles`,
`SM_Clutter_Cattails`) are **not** grid-locked props — they're placed as
scatter decoration on top of tiles and keep their own independent absolute
dimensions (see the script for exact sizes).

## 3. Ground Textures

| Property | Value |
| :-- | :-- |
| **Resolution** | `512 x 512 px` per map (BaseColor, Normal, ORM) |
| **Coverage per texture** | `1 grid cell` (`1m x 1m`) |
| **Texel density** | `512 px / meter` |
| **Format** | PNG, 8-bit per channel |
| **Maps required per ground type** | `T_Ground_<type>_BaseColor.png`, `T_Ground_<type>_Normal.png`, `T_Ground_<type>_ORM.png` |
| **Location** | `Homesteader/Assets/Homesteader/Assets/Ground/Textures/<type>/` |

512 px/m was chosen because it exactly matches the existing 512x512 ground
texture set (`black_top`, `bricks`, `concrete`, `dirt`, `farmland`, `grass`,
`gravel`, `flagstone`, `forest_floor`, `deep_water`, and the rest of the 20
current ground types) once each texture is mapped 1:1 onto a single 1m tile.
No existing texture files need to be regenerated — only the mesh UV scale
needed to change to match them (see §4).

### 3.1 Every Ground Texture Must Fit In One 1x1 Grid Cell

This is the hard rule, not just a guideline, and it never changes:
**every ground texture file is always exactly one `1m x 1m` grid cell —
one `512x512px` image = one tile. No exceptions, no multi-tile textures.**
It must read correctly when placed on a single tile *and* when the same tile
is repeated edge-to-edge across dozens of adjacent grid cells.

Note on terminology: elsewhere in this doc (and in code) "grid" is also used
to mean the *internal facet subdivision inside a single tile* — e.g. a
"`2x2` heightfield grid" means that one tile's surface is built from 2x2=4
cells (8 triangles) of low-poly detail. That is unrelated to, and never
changes, the fact that the texture as a whole is one grid cell. Don't
confuse "N facets across this one tile" with "N grid cells."

Concretely, that means:
- **No baked-in multi-tile scenes.** Don't encode a whole cross-section
  (e.g. "grass shoulder → gravel crown → grass shoulder" for a road, or a
  path with grass borders on both sides) into one texture — that composition
  only makes sense at multi-meter scale and repeats into a nonsensical
  striped/zebra pattern once tiled. If a feature needs neighboring context
  (a road's shoulder, a path's grass border), that context comes from
  placing a *different* ground type in the *neighboring* grid cell, not from
  painting it into every tile.
- **No baked-in scene-specific decoration that assumes a single placement**
  (e.g. one lane stripe painted down the middle of an asphalt tile) unless
  that decoration is meant to repeat identically on every single placed
  tile of that type. When in doubt, keep the base material type uniform and
  undecorated; add markings as a separate overlay/tile type instead.
- **Self-contained pattern elements are fine** (rows of brick courses, a
  2x2 arrangement of concrete panels, a scatter of pebbles/leaves/lily pads)
  as long as the *whole pattern* lives inside the one tile and continues to
  read sensibly when that tile repeats next to a copy of itself. These
  patterns are internal detail within the one grid cell — they are not
  additional grid cells.
- Use `ensure_seamless()` in `generate_ground_textures.py` on every
  generated texture — it blends opposite edges so tile boundaries don't
  show a hard seam.

When adding a **new** ground type:
- Author BaseColor/Normal/ORM at `512x512px`.
- Design the texture as a generic, uniform `1m x 1m` patch of that surface —
  never a wider scene. Ask "does this still make sense if I see it repeated
  9 times in a 3x3 block?" before finalizing.
- Name it `T_Ground_<type>_<Map>.png` and drop it in its own subfolder under
  `Assets/Ground/Textures/`.
- Run `tools/generate_ground_meshes.py` after adding the type to
  `GROUND_TYPES` in that script to generate the matching mesh + `.mtl`.

If a surface genuinely needs a sharper close-up look (e.g. a hero courtyard
material), it's acceptable to author at `1024x1024px` instead — this doubles
texel density to `1024 px/m` for that one material only. Document the
exception next to the texture files if you do this; don't silently mix
densities across the standard ground set.

### 3.2 Visual Style

Ground textures should read as the same material world as the item icons in
[ITEM_ICON_STYLE_GUIDE.md](file:///c:/Users/casey/Desktop/Homesteader/docs/ITEM_ICON_STYLE_GUIDE.md):
bold, chunky, low-poly facets lit by a warm top-left key light with a soft
ambient fill (never crushed to near-black), colors drawn from the same
material palette (§2.4 of that guide — turf greens, honey/cedar wood tones,
slate/gunmetal grays, warm earth browns). Facet counts should stay very low —
a `2x2` internal facet subdivision (4 cells, 8 triangles, all still inside
one 1m tile) is the standard baseline in `generate_ground_textures.py`'s
`flat_facet_field()` helper, and modular
patterns (brick courses, concrete/flagstone panels, plank rows) should favor
fewer, bigger units over finer subdivision. Any scatter accents (stones,
leaves, blades, lily pads) should stay sparse (roughly 5-20 elements per
tile) and oversized rather than dense and noisy — a ground texture should
look like a simplified, tileable extension of the item icons, not a
separate busier art style. When in doubt, simplify further: fewer facets,
fewer scatter elements, bigger shapes.

## 4. Why This Changed (history)

**Mesh scale (2026-09):** Ground tile meshes originally used a `200cm` (`2m`)
footprint while the grid system was already standardized on `100cm` (`1m`)
tiles. This meant one ground mesh tile silently spanned two grid cells,
which would have broken 1:1 alignment between ground tiles and building
placement/snapping down the line. `TILE_SIZE` in `generate_ground_meshes.py`
was changed from `200.0` to `100.0` and all 26 ground meshes were
regenerated to close that gap.

**Texture style + tiling (2026-09):** The original 20 ground textures were
generated by a dense, purely-procedural noise algorithm (12-16 cell grids,
hundreds of scattered micro-facets) that looked busy and inconsistent with
the item icons, and `farmland` was outright broken (near-black banding
artifacts). `generate_ground_textures.py` was rewritten around a shared
"big clean facet" helper (`flat_facet_field()`) using far fewer, larger
facets and the item icon material palette, and all 20 types were
regenerated. Separately, `road`, `path`, and `black_top` were found to
violate the "fits in one grid cell" rule — they baked a multi-meter
cross-section (shoulders/ruts/lane stripe) into a single tile, which would
tile into a repeating zebra-striped mess. All three were rebuilt as
uniform, self-contained 1m materials (§3.1).

## 5. Ground Tile Blending

Adjacent tiles of different ground types (e.g. grass next to mud) blend
softly at the seam instead of showing a hard edge, via an automatic
"autotile" system — see
[GROUND_BLENDING_SETUP.md](file:///c:/Users/casey/Desktop/Homesteader/docs/GROUND_BLENDING_SETUP.md)
for the full setup (a new `M_Ground_Blend` material to build in-editor, a
one-time texture import pass, and how to place tiles with the new
`AGroundTileActor` class so they participate). In short:

- `UGroundTileSubsystem` (`Source/Homesteader/*/World/GroundTileSubsystem.*`)
  tracks ground type per grid cell and auto-blends each tile against its
  highest-priority differing neighbor using one of 16 precomputed soft-edge
  masks (`scripts/generate_blend_masks.py`,
  `Assets/Ground/BlendMasks/T_GroundBlendMask_00..15.png`).
- Hardscape types (`road`, `black_top`, `concrete`, `bricks`,
  `wood_planks`, `flagstone`) never blend — a crisp edge is correct there.
- Placing ground requires `AGroundTileActor`, not a plain `StaticMeshActor`,
  so the tile self-registers with the blend subsystem.

> **Note:** The ground tile blending subsystem (`UGroundTileSubsystem`,
> `AGroundTileActor`) was originally written for Unreal Engine 5. The Unity 6
> port of this system is planned but not yet implemented. The blend masks and
> texture assets are engine-agnostic and ready to use; only the C++ actor/subsystem
> needs a C# MonoBehaviour equivalent.

## 6. Quick Reference

```
1 grid cell      = 1m x 1m       = 1 x 1 Unity unit
1 ground tile    = 1 grid cell   = 1x1x0.2m modular mesh
1 ground texture = 512x512px     = covers 1 ground tile = 512 px/meter
```
